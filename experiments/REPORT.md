# Эксперименты: токены, контекст и температура

Проект: **ИТИС Навигатор**. Дата замеров: **2026-10-05**. Выполнено **24 облачных и 26 локальных генераций**. Суммарная стоимость облачных вызовов по полю API `usage.cost`: **$0.0095623** — меньше одного цента США. Локальные вызовы не тарифицируются OpenRouter; они используют ресурсы компьютера.

Это реальные ответы API, а не подсчёт токенов по количеству букв. Исходные запросы, ответы и счётчики сохранены в [cloud.jsonl](results/cloud.jsonl), [local.jsonl](results/local.jsonl), сводка — в [summary.json](results/summary.json).

## Методика

- Облако: `google/gemini-2.5-flash` через OpenRouter; все ответы пришли от провайдера Google.
- Локально: `qwen3.5:9b`, Q4_K_M, Ollama 0.23.2, Mac с M4 Pro. Версия и параметры модели сохранены в [ollama-metadata.json](results/ollama-metadata.json).
- Для сравнения языков: три смысловые пары RU/EN, по одному вызову на язык и задачу. Весь пользовательский промпт переведён; ответ запрошен на соответствующем языке одним предложением. Температура 0, лимит ответа 220 токенов. Примеры вымышленные, чтобы не смешивать языковое сравнение с поиском разных страниц.
- Для температуры: один и тот же русский промпт, по три генерации при 0 / 0,2 / 0,8 / 1,4, лимит ответа 180 токенов. В Ollama одинаковый набор seed 41, 42, 43 для каждой температуры; остальные параметры неизменны: top_p=1, top_k=0, min_p=0, repeat_penalty=1, presence_penalty=0, frequency_penalty=0. Это специально заданные настройки эксперимента, не штатные настройки модели. В OpenRouter seed и остальные параметры сэмплирования не заданы.
- В контролируемых языковых и температурных задачах reasoning отключён; у Qwen в контекстном тесте также think=false. В тестах приложения настройки соответствуют server/agent.mjs: temperature=0.2, max_tokens=2200, reasoning не переопределён. В облачных ответах счётчики reasoning и cached tokens равны нулю.
- Приложение проверено через настоящий runAgent и настоящий MCP-сервер: функция запроса к модели обёрнута для сохранения usage. Три независимых вопроса без предыдущей истории; поиск обращался к корпусу КФУ. Это измерение серверного агентного цикла, не нагрузочный тест браузера.

Токен — единица кодирования текста моделью, а не слово. Вход включает сообщения, системные инструкции, описания инструментов и результаты их вызовов. Выход включает сгенерированный ответ и запросы инструментов; для моделей с reasoning могут учитываться и токены рассуждения. Для одного пользовательского вопроса нужно **суммировать usage всех вызовов модели**, включая повторно переданный контекст. Документация: [OpenRouter Usage Accounting](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [счётчики Ollama](https://docs.ollama.com/api/generate).

## 1. Сколько токенов: русский и английский

Среднее на одну короткую задачу (3 задачи на язык):

| Модель | Язык | Вход | Выход | Всего |
| --- | --- | --- | --- | --- |
| Gemini 2.5 Flash | ru | 76 | 30,7 | 106,7 |
| Gemini 2.5 Flash | en | 63 | 26,3 | 89,3 |
| Qwen3.5:9b | ru | 82,7 | 33,3 | 116 |
| Qwen3.5:9b | en | 75 | 29,7 | 104,7 |

- **Gemini 2.5 Flash:** русский вход больше на **20,6%**, суммарный расход входа и выхода — на **19,4%**.
- **Qwen3.5:9b:** русский вход больше на **10,2%**, суммарный расход входа и выхода — на **10,8%**.

На этих примерах русский потребовал больше токенов. Универсального коэффициента «русский всегда дороже в N раз» нет: влияют токенизатор, содержание, перевод и длина ответа. Здесь маленькая выборка. Сравнивать языки корректнее внутри одной модели; абсолютные числа между моделями зависят также от шаблона сообщений.

### Реальный расход нашего приложения

| Вопрос | Вызовов LLM | Вход суммарно | Выход суммарно | Всего | Стоимость |
| --- | --- | --- | --- | --- | --- |
| Где находится ИТИС и как связаться с институтом? | 2 | 2801 | 330 | 3131 | $0.0016653 |
| Какие компании сотрудничают с ИТИС? | 2 | 2938 | 333 | 3271 | $0.0017139 |
| Какие стипендиальные программы доступны студентам ИТИС? | 2 | 3233 | 1169 | 4402 | $0.0038924 |

Среднее: **2 990,7 входных + 610,7 выходных = 3 601,3 токена на вопрос**, стоимость **$0.0024239**. В каждом из этих запусков было два обращения к LLM и один search_kfu: модель выбрала поиск, затем получила результаты и сформировала ответ. Трассы сохранены в [app-1.json](results/app-1.json), [app-2.json](results/app-2.json), [app-3.json](results/app-3.json). Качество и актуальность всех университетских фактов отдельно не оценивались.

**Распознанный запрос расписания — 0 токенов LLM.** Маршрут в server/api.mjs вызывает scheduleViaMcp напрямую, без runAgent/OpenRouter. MCP сам по себе не является нейросетью и не потребляет LLM-токены. Если вопрос не распознан как запрос расписания и попал в общий агент, расход уже возможен. Это вывод из маршрутизации кода, а не нулевой usage от платного API.

## 2. Что происходит при переполнении контекста

Использована локальная Qwen. В документ помещены три кода: в начале, середине и конце. Между ними увеличивалось число одинаково устроенных строк. Модель должна вернуть три кода в JSON; если кода нет — null. Один и тот же документ проверен с окнами **16 384** и **2048** токенов; лимит генерации 80.

| Строк наполнителя | Окно | Вход по API | Выход | Найдено кодов | Валидный JSON |
| --- | --- | --- | --- | --- | --- |
| 20 | 16384 | 432 | 43 | 3/3 | да |
| 20 | 2048 | 432 | 43 | 3/3 | да |
| 100 | 16384 | 1792 | 43 | 3/3 | да |
| 100 | 2048 | 1792 | 43 | 3/3 | да |
| 240 | 16384 | 4172 | 43 | 3/3 | да |
| 240 | 2048 | 2048 | 38 | 1/3 | нет |
| 450 | 16384 | 7742 | 43 | 3/3 | да |
| 450 | 2048 | 2048 | 38 | 1/3 | нет |

При полном входе **4172** токена и окне 2048 Ollama отчиталась только о **2048** входных токенах. Ответ:

```text
{
  "begin": 0183,
  "middle": 0238,
  "end": 926481
}
```

Правильный ответ: `{"begin":"714693","middle":"583027","end":"926481"}`. Начальный и средний коды потеряны: модель выдала числа из строк наполнителя вместо null. Кроме того, числа с ведущим нулём делают ответ невалидным JSON. На документе **7742** токена при окне 2048 повторился тот же тип ошибки: остался правильным только конечный код. При окне 16 384 все четыре документа обработаны правильно, 3/3 кода.

**Вывод:** в этом запуске длинный ввод был усечён до настроенного окна. Это привело к потере данных и неверному восстановлению пропущенного. Увеличение входного текста сверх окна не привело к росту счётчика входа сверх 2048. Сумма входа и всех сгенерированных токенов за запрос может быть больше окна: окно ограничивает одновременно доступный контекст, а не накопительный счётчик генерации. В других серверах превышение лимита может обрабатываться иначе; поведение OpenRouter на его максимуме здесь не проверялось.

Важно: мы переполнили **настроенное окно 2048**, а не нативный максимум Qwen. Метаданные Qwen сообщают 262 144; каталог OpenRouter для выбранной Gemini — 1 048 576. Эти максимумы не были заполнены и не проверялись. Контекстный тест синтетический, по одному повтору на размер; он показывает конкретный сбой, но не измеряет точность на всех длинных документах.

В приложении есть более ранние ограничения: передаются последние **16 сообщений**, интерфейс обрезает обычное сообщение до **9000 символов**, сервер допускает до 40 сообщений и до 10 000 символов в каждом, а тело запроса — до 40 000 единиц длины JS-строки. Это ограничения в символах, **не в токенах**. Результаты MCP добавляются позднее. Поэтому старые детали чата могут исчезнуть из передаваемой истории ещё до достижения окна модели.

## 3. Влияние температуры

Задание: написать объявление, сохранив группу 11-401, старое время 14:00, новое 15:50 и аудиторию 1306, не добавляя фактов. Таблица показывает среднее число **выходных** токенов; вход всегда одинаковый: Gemini — 96, Qwen — 112.

| Модель | Температура | Выход, среднее | Диапазон выхода | Разных текстов / 3 | Все 4 поля / 3 | Упёрлись в лимит / 3 |
| --- | --- | --- | --- | --- | --- | --- |
| Gemini 2.5 Flash | 0 | 44 | 42–45 | 2 | 3 | 0 |
| Gemini 2.5 Flash | 0.2 | 45,3 | 45–46 | 2 | 3 | 0 |
| Gemini 2.5 Flash | 0.8 | 48,3 | 48–49 | 2 | 3 | 0 |
| Gemini 2.5 Flash | 1.4 | 48 | 44–51 | 3 | 3 | 0 |
| Qwen3.5:9b | 0 | 52 | 52–52 | 1 | 3 | 0 |
| Qwen3.5:9b | 0.2 | 52,3 | 52–53 | 3 | 3 | 0 |
| Qwen3.5:9b | 0.8 | 57,7 | 50–68 | 3 | 3 | 0 |
| Qwen3.5:9b | 1.4 | 180 | 180–180 | 3 | 1 | 3 |

«Все 4 поля» — проверка наличия строк, **не оценка полной правильности**. «Разных текстов» учитывает и небольшие различия пунктуации. Разбор ответов:

- Qwen при 0 дала три одинаковых ответа по 52 токена. При 0,2 менялись обращения и формулировки, длина 52–53 токена.
- При 0,8 Qwen во всех ответах сохранила обязательные значения, но в двух добавила неподтверждённое «сегодня»; в одном — «это единственное изменение в расписании». То есть сохранение чисел не означает отсутствие выдуманных фактов.
- При 1,4 Qwen во всех трёх повторах ушла в бессвязный многоязычный текст и достигла ограничения **180 выходных токенов**. Это наблюдение для указанного набора настроек, а не утверждение о любом запуске Qwen при 1,4.
- Gemini сохранила четыре значения во всех 12 ответах, длина менялась умеренно. Но даже при 0 один ответ добавил «сегодня», а несколько ответов не соблюдали требование ровно двух предложений. Нулевая температура не гарантирует ни идентичность ответов облачного сервиса, ни соблюдение всех инструкций.

Температура меняет распределение выбора следующего токена, а не число входных токенов. Выход и стоимость могут измениться **косвенно**, если меняется длина ответа. Результат зависит от модели и остальных параметров. Документация: [параметры OpenRouter](https://openrouter.ai/docs/api_reference/parameters).

Для университетского справочного помощника по нашим наблюдениям разумно оставить **0–0,2** (в приложении уже 0,2). Проверка источников всё равно нужна. Для расписания температура не применяется, поскольку оно возвращается напрямую из данных.

## 4. Сколько токенов в день на студента

Без статистики реальных пользователей нельзя назвать наблюдаемое среднее. Ниже — **прогноз по явным предположениям**, основанный на измеренных 3 601,3 токена на один общий вопрос. Полагаем, что распознанное расписание стоит 0 LLM-токенов, а общие вопросы похожи на три протестированных и задаются с короткой историей.

Формула: **токены/день = активные студенты × вопросы на студента × (1 − доля расписания) × 3 601,3**.

| Сценарий | Вопросов/день | Доля расписания | Общих вопросов в среднем | Токенов/студента/день | $/студента/день |
| --- | --- | --- | --- | --- | --- |
| Редкое использование | 3 | 80% | 0,6 | 2 160,8 | $0.0014543 |
| Базовый сценарий | 5 | 60% | 2 | 7 202,7 | $0.0048477 |
| Активное использование | 10 | 30% | 7 | 25 209,3 | $0.0169671 |

**Базовый сценарий:** 5 вопросов в день, 3 про расписание и 2 общих → около **7203 токенов на активного студента в день**. Для **100 активных студентов** → около **720 267 токенов/день** и **$0.4847733/день**. За условные 30 одинаковых дней — примерно **$14.5432000** на модель. Это не стоимость всего сервиса: хостинг и другие расходы не включены. Среднее на всех зарегистрированных студентов будет зависеть ещё и от доли активных.

Цена посчитана по среднему фактическому usage.cost. Снимок каталога: [openrouter-metadata.json](results/openrouter-metadata.json), на момент теста $0.30 за миллион входных и $2.50 за миллион выходных токенов. При длинных диалогах, дополнительных read_kfu_page, других моделях и более подробных ответах расход может быть выше. Объём MCP-выдачи и повторное включение истории в каждый вызов влияют сильнее, чем длина самого короткого вопроса студента. Три замера — ориентир, не репрезентативная статистика пользователей.

## Как повторить

Из корня репозитория, после `npm install`, Node.js >=22.13:

```bash
# Ollama должна быть запущена, модель qwen3.5:9b уже скачана
node experiments/run.mjs local

# Ключ берётся из .env (OPENROUTER_API_KEY) или окружения
node experiments/run.mjs cloud

# Анализ существующих результатов, без сетевых запросов
node experiments/analyze.mjs
```

Анализ обновляет results/summary.json и MEASUREMENTS.md. Этот отчёт фиксирует интерпретацию исходного запуска 2026-10-05; после нового запуска выводы о качестве ответов нужно проверить заново.

Перед повторным запуском сохраните копию experiments/results, если нужны исходные измерения: файлы данного режима перезаписываются. Облачный запуск использует закреплённую Gemini 2.5 Flash. В скрипте есть предохранитель по оценке расходов $0.30; это клиентская оценка по текущим тарифам, а не установленный биллинг-лимит аккаунта. Контекстный тест выполняется локально. Для вопросов приложения требуется доступ к страницам КФУ. Повторные результаты могут отличаться из-за генерации, обновления источников, модели и провайдера.

Ключ не записывается в результаты. Скрипт анализа проверяет количество записей, согласованность вход+выход=всего и успешное завершение трёх агентных запросов. Это проверка целостности эксперимента, не проверка фактической точности всех ответов.
