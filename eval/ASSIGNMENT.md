# Практика E1–E5: требования со скриншотов

Источник: пять изображений задания, приложенные пользователем 12 октября 2026 года.

1. **E1.** Прочитать 30 ответов бота, найти минимум пять плохих. Типы: «выдумал», «не по теме», «формат», «не понял». Факты сверять с ответом инструмента в логе. Сохранить `eval/labels_v0.json`.
2. **E2.** Создать `prompts/system_v1.md`: роль и ситуация, границы, источник фактов, правило «не знаю», форма ответа. Бот читает файл. Проверить пять плохих вопросов.
3. **E3.** Три пары few-shot: обычный ответ, отказ, отсутствие информации. Файл `prompts/fewshot_v1.json`. Проверить те же пять вопросов и измерить прирост входных токенов.
4. **E4.** Финальный JSON с `answer: string`, `source_tool: string | null`, `found: boolean`. Проверить кодом, при ошибке одна повторная попытка с описанием ошибки, затем честный запасной ответ. При `found=false` не должно быть дат. Проверить 30 вопросов.
5. **E5.** Те же 30 вопросов, та же модель и температура. Сравнить v0/v1, сохранить `eval/labels_v1.json`, таблицу и коммит. Проблемы выбора инструмента учитывать отдельно: один промпт ответа их не гарантирует исправить.

Презентацию пользователь дополнительно попросил в сообщении. Она должна отражать собственные результаты проекта, а не числа из демонстрационного примера задания.
